Sections 3, 5 & 6 · Functional Scope & Edge-Case Handling

Role-Based Access Matrix & Domain Validation Rules

Every role operates within strict scope boundaries, backed by input validation, stock clamping, and credit ceiling enforcement.

Stakeholder Role Authorized Operations Restricted / Blocked Actions Enforced Business Guardrails
Platform Administrator
admin@b2b.com		 Create/edit SKUs, adjust stock, manage user activation, mark invoices paid, run automation, inspect audit log. Cannot submit buyer procurement carts (separation of duties). All price/stock overrides generate immutable audit log entries.
Wholesale Buyer
buyer@b2b.com		 Browse live stock, add items to cart, submit purchase orders, view/print own tax invoices. Cannot view other organizations' orders, edit stock, or alter invoice payment status. MOQ Enforcement (min qty per SKU), Stock Clamping, and Credit Limit Ceiling ($2,500).
Sales Representative
sales@b2b.com		 View all client orders, transition order status (Pending → Confirmed → Processing → Shipped), inspect audit feed. Cannot modify SKU pricing, deactivate users, or mark invoices paid. Status transitions require valid lifecycle state progression and log actor identity.
Warehouse Manager
warehouse@b2b.com		 Adjust physical warehouse stock counts, filter low-stock alerts, advance fulfillment to Shipped/Delivered. Cannot view financial billing totals, create SKUs, or manage user roles. Prevents negative inventory counts; triggers low-stock threshold warnings.
Sections 7 & 8 · Recommended Production Stack

Relational Database Schema & RESTful API Architecture

Designed for a React/Next.js frontend, Node.js/NestJS REST API, PostgreSQL relational database with migrations, JWT auth, and Docker deployment.

🗄️ PostgreSQL Schema (migrations/001_init.sql)

3NF Normalized 
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role VARCHAR(20) CHECK (role IN ('admin','sales','customer','warehouse')),
  company VARCHAR(255) NOT NULL,
  credit_limit NUMERIC(12,2) DEFAULT 2500.00,
  is_active BOOLEAN DEFAULT TRUE
);

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  sku VARCHAR(32) UNIQUE NOT NULL,
  name VARCHAR(255) NOT NULL,
  unit_price NUMERIC(10,2) NOT NULL CHECK (unit_price >= 0),
  stock_qty INT NOT NULL CHECK (stock_qty >= 0),
  min_stock_threshold INT DEFAULT 10,
  moq INT DEFAULT 1
);

CREATE TABLE orders (
  id VARCHAR(20) PRIMARY KEY,
  customer_id INT REFERENCES users(id),
  total_amount NUMERIC(12,2) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending',
  idempotency_key VARCHAR(64) UNIQUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE audit_logs (
  id BIGSERIAL PRIMARY KEY,
  event_type VARCHAR(32) NOT NULL,
  actor_id INT REFERENCES users(id),
  message TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

⚠️ Documented Prototype Limitations

  • Client-Side State Persistence: This interactive review build runs an in-memory reactive store; refreshing resets seeded records unless connected to the PostgreSQL backend.
  • Single-Warehouse Ledger: Current stock counts represent a unified warehouse pool rather than multi-region bin locations.
  • Simulated Payment Settlement: Invoices are marked paid manually by Admins rather than via webhook callbacks from Stripe/ACH gateways.

🚀 Production & 10× Scaling Roadmap (Section 17)

  • Concurrency & Locking: Use PostgreSQL row-level locking (SELECT ... FOR UPDATE) during order placement to prevent race conditions under 10× traffic.
  • Caching & Read Replicas: Cache high-frequency catalog reads in Redis with cache invalidation on stock updates.
  • Governance & Observability: Ship immutable audit events to append-only storage and expose Prometheus/OpenTelemetry latency metrics.

🎤 Key Viva / Interview Talking Points

  • Biggest Architectural Decision: Coupling atomic inventory deduction with Net-14 invoice creation inside a single order transaction so fulfillment and accounting never drift out of sync.
  • Validation Strategy: Enforcing constraints at both UI level (clamped quantity steppers, MOQ badges) and domain logic level (credit limit check before order commit).
  • Most Independent Problem-Solving: Designing the automated operations pipeline to eliminate manual low-stock restock calculations and overdue invoice auditing.
